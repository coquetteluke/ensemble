## 2026-11-20 (installer)

- `scripts/make-installer.sh` makes `dist/Ensemble-<version>.dmg` and `dist/SHA256SUMS` from the last commit, with no Xcode needed on the Mac that installs it. It exports the commit to `/private/tmp`, builds Release for Apple silicon with no signing team, strips debug information, signs ad hoc (hardened runtime and the microphone entitlement kept, the debugging entitlement removed), and fails if the app holds a home path, login name, team id, email address or anything shaped like a key. The disk image has the app, an Applications shortcut, `First launch.txt` and a saved window layout (`scripts/installer/DS_Store`, remade with `scripts/installer/make-dmg-layout.sh`). No Intel build: it could not be tried on an Intel Mac.
- Two things found by inspecting the first build: `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO` also drops the microphone entitlement (dictation would have been refused), and `diskutil image create from <folder>`, which macOS 27 offers in place of the deprecated `hdiutil create`, leaves `.DS_Store` out. The script now asserts both in every build.
- First launch without the engine (`EngineSetupView`, model `EngineSetup`): "Install the engine" lists the Homebrew command only when Homebrew is missing, then `brew install opencode`, each with Copy, plus Open Terminal and Check again. It looks for OpenCode every three seconds and continues by itself. Ensemble runs no installer on its own. `EngineManager.checkNow` now shares one check between overlapping callers, so Check again and the background loop cannot start the service twice. OpenCode's own `curl` installer was not offered: its script picks the newest 1.x release, and Ensemble needs 2.3.
- `docs/INSTALL.md` (linked from the README): download and SHA-256 check, install, the Gatekeeper warning explained, Open Anyway step by step, the `xattr` alternative, engine setup, sign-in, updating, uninstalling. Wording and steps checked on macOS 27.2 against the real dialogs, macOS's own text tables and Apple's guide. ## 2026-11-20 (graphical installer, Luke's request)

- Luke: a disk image with a drag-to-Applications window is not an installer. The disk image now holds one app, **Install Ensemble** (`Apps/Installer`, target `EnsembleInstaller`), with `Ensemble.app` inside its Resources. Its window has three steps (Install the app, Set up the engine, Open Ensemble): it copies Ensemble to Applications (or the home folder's Applications when that is not allowed), quits and replaces an older copy, checks the copy's signature before swapping it in, shows the engine commands with Copy and Open Terminal and moves on by itself, then opens Ensemble.
- The installer takes `com.apple.quarantine` off the copy it installs, so macOS asks once, for the installer, and not again for Ensemble. The guide says so plainly. Nothing else on the Mac is touched.
- Logic in `EnsembleKit/Install/AppInstaller.swift` (8 tests). The installer target compiles that file and `Engine/EngineSetup.swift` directly and links nothing else, so it stays small. `--destination`, `--payload`, `--render` and `--unattended` are for tests and pictures.
- `scripts/make-installer.sh` builds both targets, finishes the app, puts it inside the installer, signs the installer after it, and checks both on the mounted image.
- Found on the way: the system's app icon image carries a wide colour range, and drawing it made `ImageRenderer` tone down the whole picture. The installer flattens the icon to an sRGB bitmap first.
